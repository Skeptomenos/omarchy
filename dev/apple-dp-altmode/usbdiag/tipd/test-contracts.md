This is the test-first boundary for the selected [T1 sender diagnostic](../../../../docs/plans/dev-147-usb-startup-diagnostic.md#a1-selection--t1-tipd-sender-diagnostic-living). It is not a module, image, live probe, or proof that HPD reached a receiver.

Current source checkpoint: all 22 methods pass in the fresh reviewed sandbox, with 552 successful children and no child stderr or timeout. Independent output review confirms that scoped result. The exact working control and T1 source have distinct fixed pins. The original five-file RED snapshot and its runs remain frozen. The original 13 test bodies and three independent operation models remain unchanged. The [dated evidence](../../../../docs/evidence/dev-147-t1-offline-foundation-2026-08-29.md) records limits. The [native record contract](record-contract.md) owns the diagnostic grammar; it is not the separate capture validator.

## First checkpoint: unchanged control and genuine RED

The initial runner authenticated the working HPD control source, shared header, external definition inputs, adapters, and compiler-link inputs before extraction. It compiled the exact bodies of `tipd_init`, `cd321x_queue_status`, `cd321x_update_work`, `cd321x_typec_update_mode`, and `cd321x_connect`. It also retained the exact CD321x data table. Boundary adapters record original calls and scripted returns; they do not simulate registers, firmware, USB, DRM, or kernel scheduling.

The entry assertion uses native JSON fields `rev`, `board`, `target`, `component`, `event`, and `phase`: `dev147-tipddiag1-v1`, `j413`, `front_lower`, `tipd`, `init` or `worker`, and `begin`. These emitted labels differ from the unchanged guard inputs: compatibility `apple,j413` and referenced OF path `/soc/i2c@235010000/usb-pd@3f`. This is only a positive entry requirement, not a substitute for the later complete parser. The full 13-method initial suite includes two deliberate entry-record failures and 11 original-behavior/input checks. Its OF fixture checks are construction/operation controls; they cannot test a diagnostic target guard that does not exist yet.

Independent expected ledgers check the original decisions. A successful child returns its ledger, final state, and actual INFO records. Before production edits, the selected run completed setup and all six children, then failed exactly the two absent entry assertions. The full initial suite then passed 11 baseline/input methods and repeated those same two semantic failures, with no errors. The unchanged control emitted neither marker. Compilation, input drift, tool failure, timeout, malformed observations, or an incorrect original ledger is SETUP/functional failure, never the intended RED. The original runner, raw observations, and source pins were preserved before instrumentation.

## Operation-preservation matrix

- Init: GPIO error/presence/absence; VID error/zero/TPS25750 skip; optional power callback and patch-mode failures; mask/status/role/PSY/port/power/data errors; connector absent/present; IRQ/polling and wakeup branches. Check each exact unwind suffix and original return. Port-register failure must not unregister the port. Connect errors continue; IRQ overwrites that result but polling retains it. Cleanup errors do not replace the original result. No diagnostic may inspect an uninitialized local.
- Queue/connect: latest full snapshots, OR-accumulated XOR masks, unchanged updates and double toggles; connect sets status, snapshots, cancels, and requests the original 500 ms delay. A worker copies before clearing only the queued change masks. Scheduling results remain ignored.
- Mux: SAFE, all six valid DP pins and two invalid encodings, TBT, USB4, USB; exact precedence and matching-mode skips. Copy stack payloads at the actual mux boundary. Preserve early-return versus final `state.data` clearing. A mux failure remains ignored.
- Worker: existing mutex acquisition/release; role NONE, disconnected HPD, partner removal, SAFE mode, five Type-C setters and power notification, disconnected return, partner registration/error/PD identity, mux, unconditional final role, connected HPD, final power notification. Include null/existing/error partners, identity equality/change, non-PD identity changes, accumulated disconnection, and both HPD edges in one worker. Preserve `unregister(NULL)`. Queued bits determine USB presence; current cached bits determine direction. Role/mux errors and skips do not suppress final role or HPD. HPD is void; only call/return observations are possible.

## Candidate source checks: GREEN

The frozen RED predates the diagnostic checks. The later GREEN harness extracts the complete anchored production helper block plus both real CD321x/SN201202x data tables. It uses separate immutable source identities and preserves the original ledgers. A source-scope assertion permits only the approved four function edits, helper/include addition, and CD321x allocation-size change; `cd321x_connect`, the other tables, and every other source byte must match the working baseline. Its 552 children comprise 214 control/candidate pairs, 120 diagnostic cases, two compiles, and two ELF dependency checks. These are source seams, not a kernel or boot test.

- Extract every T1 guard, wrapper, counter, and record helper. Run identical original-operation fixtures against independently pinned control and candidate. Compare complete ledgers and final observable state, as well as the independent expectations.
- Use real pinned libfdt leaf names and the pinned Linux OF compatibility/path/refcount logic. Check front target, uppercase/later compatible entry, wrong board, rear port, missing/null node/root, alternate parent, unit-name/address/case near-misses, and same-leaf foreign-tree pointers. Balance every lookup reference before counters/records. Rejects consume no diagnostic counters.
- Allocate the exact selected data-table size in the userspace seam with checked bounds and canaries. The 23 real-FDT target/path cases cross five allocation variants: exact CD321x, exact SN201202x, a copied CD table, a short generic table, and null data. Non-CD variants must cause no wrapper conversion, OF call, tail mutation, counter, or record. Null target cases with a valid board use only the board-root reference. Init retries and two instances keep distinct generation/worker identities. Actual shared-layout compatibility remains a separate ELF/BTF/frontend gate; these shims are not ABI proof.
- Require first init-entry, explicit init outcomes, queued/stored booleans, per-init/per-worker identities, all worker terminal paths, actual mux calls versus skips, both role calls and their ignored results, both HPD call/skip branches and final terminal reason. Exhaust the global budget without changing original calls. Normal 127 must emit its automatically reserved cap 128 even when 127 itself closes a worker; removing that cap fails the source-record check. Eight bounded threads exercise the production reservation helper with real C11 atomics, including forced print-arrival reordering. Check the 384-byte bound including the INFO prefix, exact identity, and maximum generation/worker values. Artificial ID exhaustion must not leave a stale worker or emit worker-zero mux records.
- Model permitted worker dispatch after enqueue while init is still active, not impossible nested same-instance mutex execution. Do not add production synchronization, retries, cleanup, or work. The collector's test-only mutex/condition controls print arrival; it is not a new driver lock or a kernel scheduling model. Do not dispatch after modeled allocation teardown. Existing init-failure cleanup can leave queued work; this source limitation is not repaired or called safe by the harness. Partial-function helper cases deliberately lack complete init/worker traces and are not hardware or capture-acceptance evidence.
- Keep strict T1 parser tests separate: positive complete records, old/mixed identity, malformed/duplicate/oversize/loss/pair/tail failures, permitted interleaving, and inconclusive missing information. Existing Apple receiver messages are only separately correlated positive entry evidence; their absence cannot establish delivery failure.

## Execution boundary

Only the orchestrator may run the reviewed command in a fresh verified unprivileged sandbox. All inputs are read-only. `/work` holds exclusive new generated C, binaries, bounded stdout/stderr, and child result records. No host helper, production preflight, package installation, `.ko` build, image operation, live state, or hardware action belongs in this test checkpoint.

Required bindings are `/inputs/tests` (frozen test directory), `/inputs/control` (working HPD baseline), `/inputs/subject` (fixed T1 core plus the four unchanged baseline files), `/inputs/headers` (fixed header root), `/inputs/of` (five fixed OF sources), `/inputs/libfdt`, and `/inputs/link-runtime`. The executed GREEN command was `/usr/bin/python3.14 -I -S -B /inputs/tests/test_tipd_semantics.py`. Both generated executables use the same fixed compiler flags; `-pthread` supports only the bounded collector/reservation fixtures. No new runtime dependency is permitted by the retained `readelf` check. The tested private snapshot is immutable; this public contract's post-run wording does not change its source pins or results.

Historical RED command, against its frozen original inputs: `/usr/bin/python3.14 -I -S -B /inputs/tests/test_tipd_semantics.py TipdSemanticsTests.test_required_init_entry_record TipdSemanticsTests.test_required_worker_entry_record`. Its setup and paired ledgers passed before exactly two missing-record assertion failures. Its whole-file run contained 11 additional baseline/input methods and the same two failures. Do not replay or overwrite those snapshots to test the new source.

The established no-install exception uses Python standard-library `unittest` and typed dataclasses instead of pytest/Pydantic. Scripted external kernel-API boundaries are an explicit testing exception; the driver decisions and OF semantics are real source fragments, not mocks. No lint/type-check PASS is claimed for unavailable tools.
